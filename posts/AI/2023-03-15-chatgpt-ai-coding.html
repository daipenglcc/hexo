ChatGPT 与 AI 辅助编程初体验

发表于 2023-03-15 | 更新于 2026-09-23 | 分类于 AI | 评论数： — | 阅读次数：

2023 年初，ChatGPT 引爆了全球对 AI 的关注。作为开发者，AI 最直接的应用场景之一就是辅助编程。从代码生成、Bug 调试到技术方案讨论，AI 正在重新定义开发者的工作方式。本文记录了我在实际开发中使用 ChatGPT 辅助编程的一些经验和思考。

AI 能帮开发者做什么

实际用了一段时间后，AI 辅助编程在以下场景中确实能提升效率：

1. 代码生成

给出清晰的需求描述，AI 可以快速生成基础代码框架：

提示词示例：

用 Node.js + Express 写一个文件上传接口，要求：

  1. 使用 multer 中间件
  2. 限制文件大小 5MB
  3. 只允许上传图片（jpg/png/gif）
  4. 上传成功返回文件 URL

AI 生成的代码通常能覆盖 80% 的功能，剩下 20% 需要根据项目实际情况调整（如错误处理、业务逻辑、安全验证等）。

2. 代码解读

面对不熟悉的代码库或复杂的算法实现，直接把代码贴给 AI 让它解释：

请解释这段代码的作用，逐行说明：

这比搜索引擎找答案再自己理解要快得多。

3. Bug 调试

遇到报错时，可以把错误信息和相关代码一起提供给 AI：

下面的 Vue 组件在切换路由时会报 “Cannot read property ‘map’ of undefined” 错误。
请帮我分析原因并给出修复方案：
[贴上组件代码]

AI 通常能准确定位到问题（比如异步数据未加载完成时就尝试渲染），并给出修复建议。

4. 正则表达式编写

正则表达式一直是很多人的痛点，AI 在这方面效果特别好：

写一个正则表达式，匹配中国大陆手机号码：

  • 以 1 开头，第二位是 3-9
  • 总共 11 位数字
  • 前后不能有其他数字

5. 技术方案探讨

在做架构决策时，可以把需求和约束告诉 AI，让它给出不同方案的对比：

我需要为一个电商后台实现权限管理系统。要求：

  • 支持角色（Role）和权限（Permission）多对多关系
  • 支持菜单级和按钮级权限控制
  • 前端用 Vue 3 + Vue Router

请给出前后端的技术方案设计

高效使用 AI 的技巧

提示词工程（Prompt Engineering）

好的提示词直接决定了 AI 输出的质量：

角色设定

给 AI 一个身份设定能获得更专业的输出：

你是一位有 10 年经验的 Node.js 后端工程师。请审查以下代码中的安全隐患和性能问题，并给出改进建议。

迭代优化

第一次生成的代码很少是完美的，通过持续对话来迭代：

第一轮：生成基础代码
第二轮：”请添加 TypeScript 类型定义”
第三轮：”请添加错误处理和边界情况”
第四轮：”请优化性能，添加缓存机制”

AI 编程的局限性

用了几个月后，也观察到一些明显的不足：

  1. 知识时效性：AI 的训练数据有截止日期，对最新版本的 API 和库可能不准确。某次让它写 Vue 3.3 的新特性代码，生成的还是旧版 API
  2. 幻觉问题：AI 有时会编造不存在的 API 或方法，看起来像模像样但实际无法运行。要养成核实文档的习惯
  3. 上下文理解：对于复杂项目的整体架构和业务逻辑，AI 只能看到你给它的片段，无法理解全貌
  4. 安全风险：直接把公司的业务代码贴到公开的 AI 服务中存在数据泄露风险，需要注意脱敏

推荐的 AI 编程工具

工具 特点 适用场景
ChatGPT 对话式，擅长方案讨论和代码生成 技术调研、代码审查、学习
GitHub Copilot IDE 内实时代码补全 日常编码、快速补全
Cursor AI-first 的代码编辑器 完整的 AI 编程体验
通义灵码 阿里云出品，中文友好 国内开发者日常使用

一些思考

AI 辅助编程不是要取代开发者，而是改变了开发者的工作重心：

  • **从”写代码”到”审代码”**：AI 生成初稿，开发者负责审查、优化和整合
  • **从”记 API”到”描述需求”**：不需要记住每个 API 的参数，但需要能清晰地描述需求
  • 底层能力依然重要：数据结构、算法、设计模式这些基础功，决定了你能否判断 AI 输出的质量

AI 编程工具正在快速进化，保持学习和适应，让它成为提升效率的利器而不是依赖的拐杖。
